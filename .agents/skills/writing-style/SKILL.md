# 文章の書き方

このプロジェクトの Markdown 文書とコードコメントを書くときは、次を守る。

読む人がその文章だけで内容を理解できるように書き、会話や過去の版を前提としない。
ADR（設計判断の記録）を除き、現在の状態だけを記述し、変更の経緯や以前の状態は ADR に記録する。

Markdown 文書では、次も守る。

- `**...**` などの強調記法を使わない。見出しや文章の構成で重要度を示す。
- フェンス付きコードブロックは、コードやコマンドを正確に示す必要がある場合に限って使う。識別子やファイル名のインラインコードは、本文と区別する必要がある場合だけ使う。
