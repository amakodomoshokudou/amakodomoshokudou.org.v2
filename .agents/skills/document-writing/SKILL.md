# 文書の書き方

このプロジェクトの Markdown 文書を書くときは、次を守る。
- `**...**` などの強調記法を使わない。見出しや文章の構成で重要度を示す。
- フェンス付きコードブロックは、コードやコマンドを正確に示す必要がある場合に限って使う。短い識別子やファイル名はインラインコードで示す。
- 文書は stateless に書く。会話や過去の版を知らなくても、その文書だけで目的・背景・内容を理解できるようにする。
- 現在の仕様や方針を説明する文書は、現在有効な内容に更新する。
- ADR などの設計判断、issue、リリース履歴は、その時点の背景や判断を残す記録として扱う。古いという理由で削除したり、現在の内容で上書きしたりしない。状態や後継記録へのリンクを更新する場合も、過去の背景や判断は保持する。
