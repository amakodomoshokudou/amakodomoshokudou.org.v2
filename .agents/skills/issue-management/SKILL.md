# issue 管理

このリポジトリの issue は、未完了を `issues/open/`、完了を `issues/close/` に置く。1 issue を 1 Markdown ファイルで管理する。

## 作成

- ユーザーの依頼から、内容を表す短いタイトルと本文を作る。情報が足りなければ分かっている範囲で記録し、必須事項が不明な場合だけ質問する。
- ファイル名は日本時間の作成日時 `YYYYMMDDHHmmss-title.md` とする。`title` は内容が分かる短い英小文字の kebab-case にする。例: `20260924101711-fix-expense-form.md`。日本語タイトルは本文の見出しに書く。
- 作成直前に時刻を取得し、同名ファイルが既にある場合は `-2`、`-3` をタイトルの末尾に付けて未使用名を選ぶ。既存ファイルは上書きしない。
- `issues/open/` に作成する。本文は `# タイトル` から始め、背景・目的は必要な場合だけ簡潔に書く。推測を確定事項として書かない。
- 対応内容と完了条件は分けず、`## TODO` にまとめる。各項目は `- [ ]` 形式で、作業や確認する内容を簡潔に書き、重複を避ける。完了した項目は `- [x]` にする。
- 作成後はファイルへのリンクを返す。issue の実装まで依頼されていない場合は、記録だけ行う。

## 更新・完了

- 対象が曖昧な場合は `issues/open/` のタイトルと内容から特定する。同名・類似の候補が複数ある場合だけ確認する。
- 完了を依頼されたら、必要な本文更新後にファイル名を変えず `issues/close/` へ移す。未完了の作業が残っている場合は、勝手に完了扱いにしない。
- 一覧や検索は両ディレクトリを対象にする。既存ファイルの内容と履歴をできるだけ保つ。
