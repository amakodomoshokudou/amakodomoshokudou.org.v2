# Git の作業手順

## ブランチ

- Git 操作の前に現在のブランチと作業ツリーの変更を確認し、既存の変更を保持する。
- コミット前に現在のブランチを確認する。`main` にいる場合は作業内容に合うブランチを作成して切り替え、作業ブランチ上でコミットする。

- `prefix` は `feat`（機能追加）、`fix`（不具合修正）、`docs`（文書）、`refactor`（動作を変えない整理）、`chore`（設定や保守）から選ぶ。
- ブランチ名は `prefix/title` とする。`title` は内容を表す短い英語の小文字とハイフンで記述する。例：`feat/shop-list`。

## コミット

- 差分を確認し、依頼された作業に関係する変更を選んでステージする。無関係な変更は含めない。
- コミット名は `prefix: title` とする。`title` は変更内容を日本語で簡潔に記述する。例：`feat: todo一覧をデータから生成する`。
- コミットは、変更内容を一文で説明できる単位に分ける。
- コミットの説明文を付ける場合は、必要な理由や変更点だけを簡潔に記述し、長くしすぎない。
- コミット後に結果と作業ツリーを確認する。

## リモートとの同期

- リモートとの同期操作（fetch、pull、push）はユーザーが行う。Codex はブランチ作成とローカルコミットまでを担当し、これらの操作を実行しない。
- PR 作成を依頼された場合は、ローカルコミット後にユーザーが実行できる push と PR 作成のコマンドも提示する。ブランチ名、PR のタイトル・本文、ベースブランチは実際の変更に合わせ、コピーして実行できる形にする。
- PR 本文は必要最低限とし、変更の目的と要点を簡潔に書く。タイトルや差分から分かる内容の繰り返し、定型的な見出し、作業経緯は省き、検証結果や注意点はレビューに必要な場合だけ記載する。
